# Bots 管理与 Bots Net 共享第一版需求与权限设计

日期：2026-10-13。状态：后续规划，尚未开发。规划条目：AN-MULTIUSER-001、AN-BOT-SHARE-001。

第一版允许 Bot 所有者或管理范围内的平台管理员邀请同一 Bots Net 服务实例中的其他已注册用户，按角色和资源范围共享使用。Bot 保持单一所有者；每位使用者默认拥有独立会话、执行上下文和私人记忆。服务端负责跨用户授权，Host 负责执行时落实同一权限边界。

## 管理入口与产品命名

2026-10-13 用户确认：本轮原型主入口为服务端平台管理员的 Bots 管理界面。集中管理不同用户已纳管的 Bots，不以“我的 Bot”和个人身份切换作为管理控制台主入口。客户端个人使用与跨设备协作仍位于现有 Agent Net，后续产品显示名规划为 Bots Net；本次不改真实客户端名称或协议 namespace。

平台管理员、Bot 所有者、Bot 共享管理员是不同主体：

| 主体 | 管理范围 | 本轮界面位置 |
| --- | --- | --- |
| 平台管理员 | 当前实例中明确纳管的跨用户 Bots；治理元数据、共享关系、资源上限内授权、额度与审批策略 | 服务端 Bots 管理控制台，原型默认入口 |
| Bot 所有者 | 自己 Bot 的所有权、可共享能力与资源上限；私人会话和凭据保持独立边界 | Bot详情显示归属；个人操作在客户端 |
| Bot 共享管理员 | 仅某个 Bot 内的委派管理，不能跨 Bot 管理或扩权 | Bots Net 的授权内功能，不等同平台管理员 |
| 使用者与协作者 | 被分享 Bot 的授权内使用、独立会话和指定资源协作 | 客户端 Bots Net；原型的次级用户体验 |

平台管理员不自动获得 Host OS 管理、所有者私人会话正文、凭据导出权或未纳管本地 Bot 的管理权。共享配置只能在 Bot 已声明的可共享上限和平台策略内调整；管理员不能通过配置把不可分享资料变为可分享。

管理员主流程是 Bots目录 → 搜索/筛选 → Bot详情 → 共享成员和权限 → 额度/审批 → 暂停共享或撤销 → 用量与审计。个人邀请接受、对话与协作是次级验证路径。暂停共享只阻断该Bot的网络调用，不表示停止Host进程。

## 多用户服务端前提

服务实例、网络、账号、设备、Bot 和会话是不同概念。同一个服务实例承载多账号；进入同一实例或网络，不自动获得其他用户的 Bot、设备或数据权限。每个 Bot 都要有明确所有者，每次调用都要有真实调用者。

第一版采用个人所有权和显式共享关系，不要求先建立组织租户、部门或企业角色体系。数据结构预留未来团队所有权的扩展点，但不能用 network ID 代替用户身份或资源所有权。第一版不支持跨服务实例或跨独立网络信任域分享。

认证主体从服务端验证的账号会话取得；客户端提交的 user、owner、network 字段不构成授权依据。权限检查覆盖 API、分页、搜索、下载、实时订阅、后台任务和 Host 调用，不只覆盖页面入口。

## 第一版范围

| 能力 | 第一版要求 |
| --- | --- |
| 指定用户邀请 | 所有者或授权范围内的平台管理员选择可用的注册用户，指定角色、资源和有效期；接收者登录指定账号后主动接受 |
| 共享入口 | 平台管理员在 Bots 详情管理纳管共享；接收者在客户端 Bots Net 的“共享给我”查看 |
| 角色与范围 | 所有者、使用者、协作者、Bot 共享管理员；角色仅是权限模板，实际授权还受资源、额度和操作限制 |
| 独立会话 | 各使用者分别创建会话和任务；需要协作时显式分享指定任务或成果 |
| 资源授权 | 仅开放所有者选中的知识库、目录、工具和业务资源；未授权资源默认不可访问 |
| 用量控制 | 每位用户有调用频率、并发数和周期用量上限；高成本或超阈值任务进入审批 |
| 撤销与过期 | 随时撤销，支持到期；下一次受保护操作前重新检查权限 |
| 操作审计 | 记录实际调用者、Bot 所有者、执行身份、授权版本、操作、结果及用量归属 |

公开分享链接、匿名访问、转分享、私人 Bot 所有权转移、跨实例联邦、企业组织体系、多人同时编辑同一配置和商业支付结算均不进入第一版。可选的邀请接受入口必须绑定目标账号；持有入口本身不能取得使用权。

## 核心流程

1. 平台管理员在服务端 Bots 目录选择 Bot 并打开共享设置（所有者在客户端仍可管理自有 Bot），选择用户、角色、允许的能力和资源、有效期、额度以及审批规则。
2. 系统生成待接受邀请。接收者在自己的账号中查看并接受；账号不符、邀请失效或撤回时拒绝。
3. 接受后形成有效共享授权，Bot 出现在“共享给我”。页面显示所有者、当前权限、费用归属、剩余额度和有效期。
4. 使用者发起独立会话。服务端确认授权，预占额度；Host 根据授权执行，返回结果和用量记录。
5. 涉及写入、对外发送、部署、敏感资源或高成本操作时，按配置提交审批，由指定有权限的审批主体处理。审批界面展示具体操作、资源、执行身份和费用；审批只覆盖该次操作。
6. 所有者或授权管理范围内的平台管理员可以修改或撤销授权；接收者可以退出共享。变更立即增加授权版本并触发相关执行上下文失效。

邀请目标可通过准确的账号标识定位，或从用户已经可见的联系人中选择；不向普通用户开放全站账号列表。邀请待接受阶段不暴露私人 Bot 配置、资源内容或历史会话。

| 对话和发起任务 | 是 | 授权内 | 授权内 | 授权内 |
| 查看自己的会话和成果 | 是 | 是 | 是 | 是 |
| 查看他人的会话和成果 | 仅显式共享 | 仅显式共享 | 仅显式共享 | 仅显式共享 |
| 读取知识和调用工具 | 授权内 | 授权内 | 授权内 | 授权内 |
| 维护共享知识与指定成果 | 是 | 否 | 指定资源内 | 指定资源内 |
| 修改非敏感 Bot 配置 | 是 | 否 | 否 | 所有者授予的字段内 |
| 邀请成员、调整角色、撤销授权 | 是 | 否 | 否 | 所有者授予的管理范围内 |

Bot 共享管理员不能给自己扩权，不能提升到所有者，不能修改所有者或同级管理员，也不能授予超出所有者分配给自己的委派范围。邀请他人、修改共享关系和管理预算采用独立权限点，避免从“可使用 Bot”推导管理权。第一版默认关闭转分享。

所有者若没有某项外部资源的再授权权利，该资源不可分享。共享角色不能突破企业、外部业务系统或 Host 的更严格权限。

## 能力与数据范围

| 权限维度 | 配置方式 | 默认值 |
| --- | --- | --- |
| Bot 使用 | 对话、任务执行分别授权 | 仅邀请模板内能力 |
| 资料读取 | 指定知识库、目录或业务对象；明确读写范围 | 未选中的资源不可访问 |
| 工具执行 | 按工具及操作类型授权，并绑定执行身份 | 仅明确授权的低风险操作 |
| 数据修改 | 写入、删除、发送、部署分别配置；范围和审批条件独立 | 关闭 |
| 会话和成果分享 | 指定对象、接收者、只读范围及有效期 | 私有 |
| 共享管理 | 邀请、撤销、配置维护和审计分别授权 | 所有者；平台治理另需独立授权 |

有效权限由账号与实例边界、有效共享关系、角色权限、资源范围、执行身份权限、审批条件和额度共同约束。任一条件不满足就拒绝；禁止规则优先。角色模板不能扩大资源范围。

Bot 的私人历史、所有者私人记忆、未授权文件和模型凭据不进入共享上下文。经所有者明确选择、允许分发的知识可以供共享使用。新增资源或新工具不会自动加入现有授权；扩大能力或资源范围必须重新配置。

## 会话与执行隔离

每个会话归属于实际发起者，保存 Bot ID、调用者 ID、授权 ID、配置版本、执行身份和资源范围。Bot 的会话、记忆、文件、向量检索、日志、缓存、后台任务和下载入口都按这些归属隔离。

默认不共用会话级记忆、工作目录、临时文件或浏览器登录状态。共享知识与用户私有记忆分开存储。Bot 所有者和共享管理员默认只能查看必要审计元数据，不能自动读取使用者会话正文；如底层 Host 运营方技术上可接触运行数据，应在产品中说明，不承诺运行隔离等同于对基础设施所有者加密保密。

Host 必须提供执行环境和工具层面的隔离，不能只在提示词中要求模型不要读取其他用户文件。无法限定访问范围的任意 shell、全盘文件工具、共享浏览器账号和通用管理工具，第一版不得直接对共享使用者开放。Host 不具备相应隔离能力时，该 Bot 暂不可共享。

共享使用者不能发现或枚举所在 Host 上的其他 Bot、文件、设备目录和管理接口。选定任务或成果的协作分享不自动开放同一会话中的其他内容，也不授予任意续写或执行权。

## 执行身份和授权传递

每项工具明确采用以下一种身份：

- 使用者自己的连接器或业务账号：执行受该账号实际权限限制。
- 所有者明确配置的共享服务身份：只允许指定操作与资源，凭据留在受控凭据存储，由执行端按授权调用。

Bot 所有者、实际调用者、审批者、执行身份和费用承担者分别记录，不能全部记为所有者。共享服务身份的供应商费用可能由所有者承担，界面必须明确；使用者自带模型凭据时应显示其对应费用归属。

目前源码的中继路径按同一 principal 限制设备互联。后续共享应新增按 Bot 和调用范围授权的路径，保留原有设备管理路径的限制，不能直接删除 principal 比较以开放跨用户 Host 访问。

服务端签发或提供可验证的调用授权，至少绑定服务与网络、调用者、Bot、目标运行实例、授权版本、能力、资源范围、执行身份、有效期和请求标识。采用项目既有成熟的签名与校验机制；不自创密码学协议。

Host 验证调用授权和当前有效状态，再落实资源限制。Bots Net 中继无需读取端到端加密的会话正文，但不能仅凭加密通道成立就放行工具。短期凭证负责传递授权，不独立保证即时撤销；Host 还需在线校验或可证明及时失效的机制。无法确认授权当前有效时，拒绝新的受保护操作。

## 额度与费用

第一版提供用量归属和内部预算控制，不引入支付或结算系统。使用所有者配置的模型或服务身份时由所有者承担该用量；使用者自带身份时按相应账号归属。团队资金池和跨用户费用结算后续扩展。

预算同时约束 Bot 总量和每位使用者额度，并支持频率、并发及单任务上限。发起任务时原子预占预计用量，结束后用实际用量结算并释放余额；重试按请求标识去重。实际用量暂不可得时保留未结算状态，不将未知计为零。

模型成本估算须注明计价版本和估算性质；调用前可保守预估、执行中限制步骤或输出，结算后记录实际差异。不能承诺所有供应商的收费都能精确预知。额度控制也不能替代供应商余额、限流或费用授权。

超阈值请求先审批或拒绝，不默认自动扣费升级。审批绑定具体任务、身份、资源、预算和授权版本；配置或授权发生变化时需要重新确认，不复用不匹配的批准。

## 撤销和异常语义

| 情况 | 第一版行为 |
| --- | --- |
| 邀请撤回或过期 | 不可接受，不形成有效授权 |
| 有效授权撤销、过期或用户停用 | 拒绝新任务；失效订阅和调用授权；下一受保护操作前拒绝 |
| 正在运行的任务 | 发出取消请求，停止后续工具操作；已经完成的外部写入不自动回滚，显示取消的实际结果 |
| 管理员调整角色或资源 | 增加授权版本，废止旧权限上下文，按新范围重新检查 |
| Bot 配置扩大能力 | 现有共享不会自动扩权；需要所有者更新授权 |
| Host 离线或授权服务不可用 | 明确不可用或等待状态，不绕过校验，不切换为所有者无限权限 |
| 共享关系失效后的成果 | 用户可保留自己的、允许保留的历史成果；依赖共享资源的后续访问重新鉴权。已下载内容无法追溯收回，界面明确说明 |
| 用户退出共享 | 停止共享访问，不自动删除本人会话；按独立保留与删除策略处理 |

撤销作用于未来访问和尚未完成的执行步骤；不能承诺收回接收者已合法取得的文件，也不能承诺逆转正在由外部系统执行的动作。事件推送用于及时更新界面，后端鉴权才是实际权限依据。

## 服务端概念模型

以下是逻辑对象，不是已确定的数据库表或接口实现。

| 对象 | 关键归属与关系 |
| --- | --- |
| Principal | 验证后的用户主体；与认证提供方标识稳定映射 |
| PlatformAdminGrant | 平台治理授权，绑定主体、实例和纳管范围、允许动作与有效期；独立于 Bot 共享管理员 |
| Device 与 Host | 所属主体、网络、身份状态；管理权独立于 Bot 共享 |
| Bot | 所有者、配置版本、运行实例映射、可共享能力上限 |
| Invitation | 邀请者、指定接收主体、Bot、拟授予范围、有效期、接受状态 |
| ShareGrant | Bot、授予者、接收主体、角色、能力、资源、额度、版本、有效期和撤销状态 |
| ResourceBinding | 资源范围、执行身份引用、读写权限和审批规则；不存原始凭据 |
| Session 与 Task | 实际发起者、Bot、授权及配置版本、独立上下文和执行状态 |
| ArtifactGrant | 指定任务或成果的只读分享关系，不默认继承完整会话 |
| UsageReservation 与 UsageRecord | 费用承担者、调用者、Bot、预算周期、预占、结算及实际用量 |
| AuditEvent | 操作者、对象、动作、授权与配置版本、身份引用、结果、时间和请求关联 |

服务端在同一受控操作中确认授权并预占额度，使用版本检查处理权限修改与任务启动之间的竞争。最终持久化方案、外键范围、接口及协议兼容策略在开发前审查。

服务端管理员界面需要“Bots”“Hosts”“用户与权限”“操作审批”“用量与审计”等明确入口；客户端 Bots Net 提供“我的 Bot”“共享给我”“待接受邀请”和独立会话。错误状态区分未授权、已过期、额度不足、待审批、Host 离线和配置变化，不以重新登录掩盖所有错误。

审计记录共享创建、接受、权限修改、撤销、拒绝、审批、工具执行和用量结算；日志不保存原始凭据或默认记录完整会话正文。审计查询也按资源和主体授权，保留周期及导出权限在实施时确定。

## 后续验收标准

以下均待开发后验证，本次不执行测试或真实业务写入。

- [ ] 平台管理员仅能管理纳管范围内的跨用户 Bots；平台管理员与共享管理员不能互相冒充，私人上下文和凭据不自动开放。
- [ ] 至少三个独立账号：A 为所有者，B 为被邀请用户，C 无授权；B 只能看到授权 Bot，C 不能访问或枚举相关私有对象。
- [ ] 指定账号接受邀请；错账号、重复接受、过期和撤回均产生正确结果。
- [ ] 使用者、协作者、管理员权限与矩阵一致；管理员无法自行扩权或取得 Host 管理权。
- [ ] B 的会话、记忆、临时文件、搜索、下载、订阅和后台任务与 A、C 隔离；所有者默认无法经产品界面读 B 的私人会话。
- [ ] Host 执行验证真实调用者和资源范围；直接构造 API、重放旧授权、调用未授权工具及跨 Bot 访问均被拒绝。
- [ ] 共享服务身份与使用者自带身份分别正确执行，业务系统实际权限和持久化结果一致，凭据不暴露。
- [ ] 撤销和到期阻断新任务及后续受保护步骤；重连、重启、缓存和旧订阅均不能恢复已撤销权限。
- [ ] 修改授权、资源或配置的并发场景不会放大权限；已批准但范围不匹配的操作必须重新审批。
- [ ] 并发预占不会透支内部额度，重试不会重复计费；未知用量、失败、取消和供应商拒绝可追踪。
- [ ] Bot、Host 和共享服务重启后，授权、会话归属、用量及审计保持一致。
- [ ] 桌面与必要移动页面完成真实邀请、接受、使用、审批、撤销路径，含键盘和错误恢复。
- [ ] 在授权测试身份与可控数据下完成真实多用户联调，并分别记录模拟验证、生产验收、源码提交、主干同步及发布对应关系。

## 开发前必须落实的设计问题

1. 核实最新服务端身份、网络和路由实现，以及 Bot 与 Agent、工作区和运行实例之间的实际映射。
2. 选定能隔离文件、工具、浏览器和凭据的 Host 执行方案；不满足隔离的 Bot 不开放共享。
3. 明确授权传递、在线校验、撤销传播和运行任务取消机制，保留现有设备管理边界。
4. 确定邀请账号定位方式、默认角色模板、额度计量及审计保留规则。
5. 制订持久化与协议兼容方案，保持已有个人 Bot 与设备的归属，不把历史数据自动开放给新用户。

本次设计已覆盖上述问题的约束；实现方案、数值阈值与开发排期尚未确定。接续入口见[Bots Net 后续规划](AGENTNETS-ROADMAP.md)。

## 与管理员生命周期的联动

用户追加的纳管Bot创建、配置、启停、删除与所属用户/Host分配按[Bots生命周期规划](BOT-ADMIN-LIFECYCLE-V1.md)处理，属于独立平台授权，不授予Bot共享管理员。仅原型和规划，不表示真实管理功能已实现。停止阻断该Bot新任务和受保护写入，暂停共享不停止Bot。归属/Host变化和逻辑删除撤销原共享、邀请及不匹配审批；恢复或重启不自动复活原授权。私人上下文不转移，历史成果仍按原发起者授权；原版不开放私人Bot所有权转移的边界保持。
